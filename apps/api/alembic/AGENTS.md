# Migration instructions

These rules extend the root `AGENTS.md` and `apps/api/AGENTS.md`. Read both first.

## Rules

- Read `docs/architecture/DATABASE.md` before writing or modifying any migration.
- One migration file = one coherent schema change. Never bundle unrelated changes.
- Review autogenerated migrations manually and remove any unrelated detected changes
  (Alembic sometimes picks up noise from other tables).
- Never rewrite or delete a migration that has already been applied to any database.
  After deploy = append-only.
- Never drop a column or table without a backup plan documented in the migration comment.
- After adding a new table or column, update `docs/architecture/DATABASE.md`.

## Commands

```bash
# Apply all pending migrations
cd apps/api && uv run alembic upgrade head

# Create a new migration (after editing models.py)
cd apps/api && uv run alembic revision --autogenerate -m "short_description"

# Check current state
cd apps/api && uv run alembic current
```
