# Settings Module — Deep Dive

Small on purpose — this is the one module that's mostly UI over things already designed
elsewhere, not new architecture.

## 1. Reminders & Email Notifications

```
NotificationSettings   (singleton)
  email_address
  digest_enabled    bool, digest_frequency: "daily" | "weekly"

ReminderRule
  id, source_type: "calendar_event" | "finance_deadline" | "fitness_goal"
  lead_time          # e.g. "30 minutes before", "1 day before"
  enabled            bool

ReminderJob            # generated by the scheduler, not user-created directly
  id, rule_id FK, related_id, send_at, sent_at | null, status
```

Reuses the same background scheduler already planned for recurring event/transaction
materialization (Calendar §2, Finance §2) — reminders are just another scheduled job type
on the same infrastructure, not a separate system.

**Practical note on sending the actual emails**: self-hosting outbound email reliably from
a VPS is a notoriously painful path (SPF/DKIM/DMARC setup, reverse DNS, and VPS IP ranges
get flagged as spam sources easily regardless of how correctly configured). Worth using a
small transactional email provider (e.g. Resend, Postmark) rather than raw SMTP from the
VPS — cheap or free at the volume a single-user app needs, and it sidesteps a deliverability
problem that has nothing to do with how well the rest of this is built.

## 2. Account Security

Straightforward UI over what's already specced in `AUTH_AND_SECURITY.md`:
- **Change password** → existing auth endpoint, current-password confirmation required.
- **2FA enroll/disable** → TOTP QR code setup, same as already designed.
- **Active sessions** → list of valid refresh tokens (device/IP/last-used), with a "log out
  this device" action — cheap to add given the session model already tracks this.

## 3. General Settings

- **Home currency & default timezone** — the settings already required by Finance (§7/§8)
  and Calendar (timezone handling) live here as the single place they're configured, rather
  than being buried in each module.
- **Theme** — light/dark toggle, per `docs/design/STYLE_GUIDE.md` (dark default, as decided).
- **Google Calendar connection** — status, reconnect, disconnect.
- **AI provider configuration** — `AISettings` from `AI_ASSISTANT_MODULE.md` §2 lives here:
  pick provider, enter API key or local endpoint, set autonomy level.
- **Data export** — a "download everything" action (full JSON/zip export of your own data).
  Worth including on principle for a system holding this much of your life — an explicit
  escape hatch, even if you never use it, matters for trust in a self-hosted personal system.
