- **§2 Ponytail — mandatory.** Laziest solution that works. Stop at the first rung of the
  ladder that solves the problem. Mark every deliberate shortcut with a
  `# ponytail: <reason>` comment naming the ceiling *and* the upgrade path.
  Deliberate v1 cuts below are tagged **[PONYTAIL]**.

  containing all five sections. Not optional.
- **§6 Verify before done.** Backend gate is `cd apps/api && pytest`. The branch ships
  **153 green tests**. Keep them green; every new endpoint adds tests.
- **Decimal discipline.** `Numeric(38,18)` / `Numeric(24,8)` in the DB, `DecimalString` on
  the wire. **Never** introduce a float into a finance code path. The existing
  `_no_float()` guard and the `decimal_string()` helper exist for this — use them.
- **Append-only law.** Migration `034_finance_immutability.py` installs DB triggers that
  forbid `UPDATE` on the event tables. An "edit" is **a new superseding revision**, never a
  mutation. Do not fight the triggers, do not disable them in tests.
- **Migration chain.** `028 → 029 … → 038` is linear and clean. Do **not** renumber, delete
  or reorder anything — including `033_finance_ai.py`, whose tables become orphaned when the
  assistant is deleted in B11. **[PONYTAIL]** orphan tables are harmless; a drop migration is
  new risk for zero user value.
- **Idempotency.** Every mutating route takes `Idempotency-Key` and appends to the
  hash-chained audit log. New mutations in B1/B2 follow the same pattern as the existing
  routes — copy, don't invent.

## Phase B1–B11 — Backend additions (~1,000 LOC) + assistant deletion

All routes under `/api/finance`. New service logic goes beside its neighbours in
`apps/api/app/services/`, routes in `apps/api/app/routes/`.

### B1 · `POST /api/finance/events` — manual "Add record"
The single largest gap: **the whole API is read-side + import-side. There is no way for a
human to enter one transaction.** The mockup's "+ Add record" button has nothing to call.

- Body: `{tax_year, occurred_at, event_type, amount (DecimalString), currency,
  source_account_id, description, jurisdiction, asset_id?}`
- Reuse `finance_import_projection.py` helpers — do **not** write a second write path.
  A manual event is an import of one row with `derivation_type="manual"` and
  `created_by_type="user"`.
- Creates `finance_events` + `finance_event_revisions` + `finance_event_components` +
  `finance_valuations` in one transaction.
- `Idempotency-Key` required; route through `_record_audit_entry`.
- Tests: `apps/api/tests/test_finance_manual_events.py` — happy path, idempotent replay,
  float rejection, bad jurisdiction Literal.

### B2 · `PATCH /api/finance/events/{event_id}` — edit as append-revision
- Body: `{expected_revision_id, ...changed fields}`.
- **Optimistic lock**: mismatch → `409` with the current `revision_id` in the body so the UI
  can offer "changed elsewhere — reload?".
- Appends a revision with `supersedes_revision_id` set. Never updates in place.
- Tests: revision chain correctness, 409 path, audit entry appended.

### B3 · `GET /api/finance/timeseries`
Powers all three charts on the Overview page. **There is currently no timeseries endpoint at
all** — `/summary` returns scalars only.

- Query: `metric` ∈ `net_worth | income | expense | rewards | readiness`,
  `granularity` ∈ `day | week | month`, `group_by` ∈ `account | source | jurisdiction | none`,
  `tax_year`, optional `from`/`to`.
- New service `apps/api/app/services/finance_timeseries.py`: `date_trunc` + `SUM` over
  `finance_postings` ⋈ `finance_event_revisions`.
- Response: `{series: [{key, label, points: [{t, v: DecimalString}]}]}`.
- `rewards` at `granularity=day` is what the mockup means by *"tiny hourly rewards are grouped
  by day for clarity"*.
- **[PONYTAIL]** computed per request, no cache. Add caching only when a real page is slow.
- Tests: `apps/api/tests/test_finance_timeseries.py` — bucket boundaries, empty ranges,
  grouping, decimal fidelity.

### B4 · `previous_year` block on `GET /summary`
The five KPI cards each show a YoY chip (`↑12% vs 2025`). One extra query, same shape as the
existing totals block:
```
"previous_year": {"income": "...", "expense": "...", "rewards": "...", "transfers": "...", "net_worth": "..."}
```
Percentages are computed **client-side** — do not send a float ratio.

### B5 · `GET /api/finance/review-queue/counts`
Feeds the sidebar WARNINGS cards and the Review page filter badges. Four buckets:
`{needs_grouping, needs_evidence, ready, problematic}` + `total`.
Derivable today only by fetching every group — hence this endpoint.

### B6 · Filter params on `GET /activity` and `GET /review-groups`
Add `event_type` and `group_id` query params to both. Small change, unblocks the TODAY table
filters and the Review page. Extend existing tests rather than adding a file.

### B7 · `GET /api/finance/evidence/bundle`
`StreamingResponse` ZIP with numbered folders, keyed off `evidence_documents.source_kind`:
```
01_payslips/  02_exchange_statements/  03_wallet_exports/  04_contracts/  05_residency_evidence/
```
- Query: `tax_year`, optional `jurisdiction`.
- Reuse the existing `_zip_bytes` / deterministic-manifest pattern from `finance_reports.py`.
- Tests: `apps/api/tests/test_finance_evidence_bundle.py` — folder map, manifest determinism,
  jurisdiction filter.

### B8 · `?category=` filter on `POST /reports`
Reports page row 2 has per-category packages (income, funds, gold, crypto spot, crypto
staking …). Today ZIP splits by *schedule*, not category, and there is no per-category route.
Add `category` to the report request body; categories are enumerated from the
`tax_treatment_revisions` present in the year.

### B9 · Real PDF generation — replace `_pdf_bytes`
`_pdf_bytes` is currently a placeholder. This makes "Export full PDF report" honest.

- **Dependency decision required from the user before adding anything.** Options:
  `reportlab` (pure Python, no system libs — recommended), or WeasyPrint (needs
  cairo/pango/gdk-pixbuf; heavier). **Do not add a dependency without explicit approval
  (AGENTS.md §6).**
- Multi-page: cover, per-schedule tables, repeated headers, citations/lineage ids.
- Tests: `apps/api/tests/test_finance_reports_pdf.py` — assert byte markers (`%PDF-`, page
  count). **[PONYTAIL]** no `pypdf` test dependency just to read back our own output.

### B10 · PDF statement import — generic, no per-bank parsers
New pipeline in `apps/api/app/services/finance_pdf_statements.py`, feeding the **existing**
`/imports/preview` → `/imports/{id}/commit` flow. Do not build a parallel import path.

- `pdftotext -layout` → per-line regex heuristics for `date / description / amount /
  currency`, plus a per-row `confidence` ∈ `high | medium | low` and an
  `unparsed_line_count` on the preview response.
- Rows are **editable in the preview** (Claude builds that UI) — commit accepts corrected rows.
- Reuses the existing 3-layer dedupe (`file_fingerprint` / `row_fingerprint` /
  `provider_fingerprint`) unchanged.
- **[PONYTAIL]** generic line heuristics only. Per-bank layouts are the single largest
  unbounded item in the spec — **explicitly out of scope for v1**, upgrade path is a
  per-provider template table.
- Tests: `apps/api/tests/test_finance_pdf_import.py` with a small fixture PDF.
